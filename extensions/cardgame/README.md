# CardGame 桌面后台

本目录保留 CardGame 内容、资源、生产、候选采用、对局分析和预览的原有业务实现。`plugin.ts` 使用 Worka 公开宿主接口注册；`project-binding.ts` 管理用户为当前桌面选择的项目和服务生命周期。

普通 `bun run build` 会先准备六个内容库的共享源码，再把声明的后台运行文件打包到桌面制品。宿主接口及 sharp、music-metadata 是共享 peer，不在包内复制原生二进制。`dist/plugin.js` 是本目录源码的编译结果；修改后运行 `bun run build`，不要单独修改生成清单。

项目服务按桌面和项目根目录隔离。未配置时只有安全的配置状态，既不猜测项目路径，也不读宿主历史配置。目录切换排空已接收请求、释放订阅、关闭原有服务并停止该桌面预览；绑定保存失败会恢复配置投影，旧绑定仍然有效。

当前实现来源于维护者提供的实际本机 CardGame 扩展源码，迁入本仓库后移除了旧宿主项目配置文件和部署路径约定。游戏项目保持独立。

项目绑定使用落盘的 opaque generation，不以路径字符串作为身份。旧绑定首次原地升级只迁移一次，写入失败不开放事件。目录切换更换 generation，旧编辑与旧回执失败关闭；原地升级的无代次轮次仅允许核对原执行任务，不重放未知副作用。

生产事件只携带冻结轮次身份，服务统一准备去重键，关系脚本从 canonical 查询读取交办快照。state、数据库与 events 仍是独立持久步骤；丢失绑定或候选回执沿用原操作重试。资源候选必须有本轮输出目录内真实文件及资源服务回执，迟到结果与派发回执保留历史而不回退当前轮次。

卡面布局和操作名从 note-4 的单一源码编译。中文 PNG 仍依赖运行环境的可用字体或宿主提供的字体路径，沿用已有系统字体查找；缺失时可能出现缺字或外观差异，本轮未消除这项环境依赖。当前 Linux / sharp 0.35.4 渲染已测，未做跨操作系统验收。

## 内容库源码的唯一来源

`plugins/cardgame-content/src/contract.ts` 是唯一公开契约源码。正常后台构建开始时，`scripts/materialize-content-notes.ts` 自动把原始字节复制到 note-1、note-7、note-8、note-9、note-10 和 note-12 的 `contract.ts`，逐个核对 SHA-256。该文件只能静态导入 `@realiz3r/worka/extension-contracts` 公共入口或 `zod`，不能导入后台实现、本地文件、宿主接口或动态加载器；检查不会执行契约代码，也不扫描后台目录。这个导入检查是维护边界，不是 JavaScript 安全沙箱。

六个内容库的业务源码以 `notes/note-1` 为准。普通构建通过 Worka 公开构建入口复用已有发布闭包，跟随实际代码、类型、嵌套模块、本地图片及业务包依赖，再同步完整共享库存，不扫描无关草稿或要求作者维护源码清单。修改公共视图、动作或模型应改 note-1；公开输入输出 schema 应改后台的唯一 `contract.ts`。各实例的 config 文件、README、SKILL、图标、便笺名称、桌面配置和预构建产物保持独立；共享代码需要的依赖与发布源码列表自动合并，其他额外依赖和资源保留；实例自己的锁文件不被另一实例的锁文件覆盖。已同步的旧文件只有在上一次生成清单中登记过，且已从 note-1 移除时才会删除；其他实例文件保留。

每个内容库的 `content-sources.json` 记录相对来源和精确源码 hash。准备函数支持 `mode: 'check'`，可以只校验源码、目标和生成清单，不修改文件；普通 build 使用默认同步模式，不需要增加命令或维护包清单。便笺的普通本地 import 会被 Worka 已有发布闭包自动包含。便笺构建与发布沿用 Worka 现有流程，消费已经物化的包内源码；复制源码不会冒充完成预构建。作者不需要另行运行同步、hash 校验或契约激活命令。

直接相关的隔离测试：`bun test tests/materialize-content-notes.test.ts`。这些测试只使用临时样例，不覆盖仓库中的便笺。
